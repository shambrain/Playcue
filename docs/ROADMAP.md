# PlayCue Roadmap

Phases are quality gates, not promised dates.

## Phase 0 — baseline
- [x] Product direction, Windows-first/local-first/Tauri 2 architecture documented.
- [x] Steam and Millennium integration boundaries researched.
- [x] OpenCode agents and skills created.
- [ ] Verify installed toolchain and dependency versions.
- [ ] App scaffold, CI and SQLite migration harness.

## Phase 1 — sidekick
- [ ] Secure Tauri shell and single-instance behavior.
- [ ] Steam detection, read-only multi-library discovery and fixtures.
- [ ] Standard launch handoff and error reporting.
- [ ] Orb, shortcut, tray, optional autostart, fullscreen suppression.
- [ ] Search, recents, favorites and session observer.

## Phase 2 — personal gaming memory
- [ ] WishVault manual/import snapshots and diff.
- [ ] Missing-item status semantics and archive.
- [ ] Gift Watchlist, Unified Game Search and export/restore.
- [ ] Collections and Session Notes can move into 1.1 if quality requires.

## Phase 3 — release quality
- [ ] Launch Doctor diagnostics.
- [ ] Accessibility, performance and Windows 10/11 acceptance.
- [ ] Installer/signing, update/uninstall, privacy docs and release audit.

## Phase 4 — optional browser companion
- [ ] User-triggered wishlist capture with narrow permission and authenticated bridge.

## Phase 5 — social and sync
- [ ] Threat model, SquadPulse, voluntary shared lists, Game Night Matcher.
- [ ] Optional encrypted sync, revoke/export/delete.

## Phase 6 — Deck/Linux
- [ ] Linux portability, Flatpak feasibility, controller-first Deck Mode.
- [ ] Physical Steam Deck Desktop/Gaming Mode tests.

## Phase 7 — optional Millennium
- [ ] Only if user demand supports a Steam-client-specific entry point.
- [ ] Separate package and human-maintained plugin ownership; review latest policy.
